# Decisions

Changes forced by the docs, the spike or the toolchain, with the reason. The feature is kept in every case.

- 2026-11-27 · Web design: all website design, UI and UX work (Phase 8, /docs page, /proof) runs through the award-site-design skill, per the owner's instruction.
- 2026-11-27 · Sigmoid LUT tolerance: the checklist first said < 1e-5, but linear interpolation over a 1/32 grid has a theoretical max error of h²/8·max|σ″| ≈ 1.18e-5 (measured 1.17e-5). The plan fixes the LUT at 1024 entries, so the acceptance bound is set to 1.5e-5. Effect on prices: < 0.0012 cents per share.
- 2026-11-27 · Program tests: the plan says "Anchor TS tests on localnet with MagicBlock's local ER". The current docs (local-development guide) name MagicSVM 0.3.x as the environment for delegation, ER writes, commits, VRF callbacks, validator-1.1.1 cranks, Magic Actions, eATA projection and permission-gated reads, and the base repo now tests every example on MagicSVM. Following the docs: instruction tests run on MagicSVM (Rust, `cargo +stable test`), and live behaviour (TEE privacy, router, real VRF oracle, crank cadence) is proven on devnet-tee. Nothing is dropped.
- 2026-11-27 · Node 24.10.0 pinned through Volta (`.nvmrc` added).
- 2026-11-27 01:20 IST · Public GitHub repo created at the owner's request: https://github.com/Prashant-thakur77/ringside (secret scan of tracked files and history: clean).
- 2026-11-27 · VRF callback identity: `#[vrf_callback]` injects `address = scoped_vrf_identity_const(&crate::ID)`, which runs the PDA derivation at runtime and used all 197k CU in the callback (MagicSVM log: "exceeded CUs meter"). The context now declares `vrf_program_identity: Signer` with `address = VRF_CALLBACK_IDENTITY`, a compile-time `const` of the same scoped identity. The authentication is unchanged (same key, must sign); a test sends a spoofed callback and expects rejection.
- 2026-11-27 · Finalize split: committing the 1,232-byte Match plus a post-commit action does not fit one committor transaction (local ER log: "Commit tasks do not fit in tx … 1840 bytes (max 1644)"). `finalize` now commits the live book with the MatchRecord action, `commit_match` commits the Match in its own intent (sent in the same transaction), and `cleanup_positions` commits the delayed book. The record args carry the final hash and both books' numbers, so the receipt is unchanged.
- 2026-11-27 · Local stack limit: the local ER (magicblock-core 1.1.1) sends v1 settlement transactions; the local Agave 3.1.9 test validator rejects them ("failed to deserialize VersionedTransaction"), so commits/actions cannot land locally. Commit + action logic is proven on MagicSVM (MatchRecord written) and is verified live on devnet. Local runs cover everything up to finalize.
- 2026-11-27 · Local ER runs in Docker with `--ulimit nofile=1048576` because the host hard limit is 524,288 and raising it needs root.
- 2026-11-27 · Session keys: `@magicblock-labs/gum-react-sdk` 3.0.10 `createSession` creates V1 `SessionToken` accounts, while the program validates `SessionTokenV2` (the current pattern in the docs and the base repo's session examples). The web app therefore builds `create_session_v2` itself with the gum SDK's program client (`SessionTokenManager.program`): an in-browser session keypair, scoped to Ringside, valid 2 h, small lamport top-up, signed by the wallet and the session key. Same session-keys program, same 2 h scoped session; trades and inputs are then signed by the session key without wallet prompts.
- 2026-11-27 · Courtsider accounting fix: transport errors on the courtsider's stale Ringside orders were counted as fills (32 in the local dry run). They never reached the program, so they are now counted as transport errors; the local data file was corrected the same way. The program cannot fill a stale order (MagicSVM test, indexer count of Ringside fills with game_tick > seen_tick + 2 is 0).
- 2026-11-27 · devnet-tee now runs validator 2.0 (`getVersion` → `core 2.0.5`, identity unchanged `MTEWGuqx…`); the plan assumed 1.1.1. Per the current docs: SDK 0.18 supports 1.x and 2.0 (kept); on 2.0 `ScheduleTask` is forwarded to a Hydra ephemeral crank and scheduled instructions must not carry signer metas (ours carry none); tasks fire only while a `hydra-cranker` runs. Order of preference on devnet: (1) validator crank via ScheduleTask, (2) the same crank executed by our own `hydra-cranker --ephemeral`, (3) Switch A keeper. Local testing adds a 2.0 stack (ER + VRF oracle + Hydra cranker) next to the 1.1.1 one.
- 2026-11-27 · Devnet indexing on the private ER: devnet-tee does not deliver `logsSubscribe` notifications (the `all` filter is refused, program-mention subscriptions stay silent even for the sender), returns transaction logs only to the signer, and crank-executed ticks have no client-visible signature. Account subscriptions are delivered for every write (probe: 579/579 ticks, 0 gaps). The indexer therefore follows each live match by `accountSubscribe` on the Match and both Market accounts: tick rows come from Match snapshots (tick, `sim.last_inputs`, hash chain; event flags recovered by stepping the previous snapshot, which also cross-checks the chain), and fills and recorded rejections come from Market counter/inventory/cash deltas with the trader shown as "private". Strict-mode rejections are failed transactions and are visible only to their signer; the courtsider's own log covers those (E1/E2). On the local ER the log stream is used as before.
- 2026-11-27 · Devnet base RPC: the public `api.devnet.solana.com` rate-limits parallel runners (429 "Connection rate limits exceeded"), so devnet scripts, services and the web app default to MagicBlock's devnet RPC `https://rpc.magicblock.app/devnet` (same cluster, CORS open; `SOLANA_RPC` overrides).
- 2026-11-27 · Devnet crank: on devnet-tee our scheduled `tick` crank is executed by the validator itself (our own `hydra-cranker` triggered none of our tasks); matches advance "via crank" with no keeper.
- 2026-11-27 · Web host: the Vercel team is paused under Vercel's fair-use policy (402 on `vercel link`), so the web app runs on Cloudflare Workers through OpenNext (`apps/web/wrangler.jsonc`): https://ringside.prashant101007.workers.dev. Every page is a client component, so server CPU per request stays small. The WASM sim is loaded from a runtime-built URL so the server bundle leaves it alone.
- 2026-11-27 · Devnet evaluation size: each devnet match leaves about 0.09 SOL of delegation rent on L1 (positions, permissions, delegation records), so the first funded run used 2 parallel runners × 12 matches for E1 (23 complete) and an 8 × 40 soak. The scripts take MATCHES / RUNNERS / SOAK_USERS to scale up when more SOL arrives.
